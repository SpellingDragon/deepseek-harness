# Agent Note: 实时 subagent 模型授权更新

Status: implemented

[English](2026-10-24-live-subagent-model-authorization.md) | 中文

## Problem

Host 在 Session 的首个模型请求前记录其获准的 subagent 路由。因此设置编辑只影响此后创建的 Session；运行中或恢复的 Session 会保留创建时的授权，直到用户新建对话。持久快照让恢复保持确定性，却让用户在当前对话中显式修改的偏好看起来无效。同一设置卡也没有按模型设置默认推理强度的方式，省略强度时总是回退到适配器默认值。

## Decision

`subagent/model-selection-policy-change` 记录一次实时授权变更，包含 `enabled` 标志与当前保存的精确路由。既有的 `subagent/model-selection-policy` 事件仍是初始的启动记录。Session 投影折叠两种事件并暴露最新授权；关闭变更清除授权，但不丢弃设置文档保留的路由。投影折叠语义发生变化，因此状态版本递增。

当 Volatile 偏好更新时，Host 设置服务向每个存活 Agent 写入该变更事件。Agent 创建时，它把已记录授权与当前偏好比较：新的启动 Session 在授权不同时收到初始事件，恢复的 Session 收到变更事件。新 Session（包括子 Session）采用当前 Host 偏好，而不是继承父级快照。只有路由集合或某条路由的默认强度不同才追加变更事件；仅顺序不同不算变更。

每条获准路由还可以携带一个可选的默认 `reasoningEffort`。当委派调用省略 `reasoning_effort` 且其生效路由匹配某条获准路由时，执行器使用该路由的默认值；模型显式给出的值仍然优先。这是默认值，不是允许列表：适配器为该路由公布的所有强度仍然可以被显式选择。

发现与委派继续读取 Session 投影，不在每次调用时读取设置文档，因此每次授权变更都留在 Session 日志中，恢复的 Session 会重放出相同的决策序列。设置、发现与执行仍共享同一个包内授权定义。

## Alternatives considered

**每次发现或委派调用都读取当前设置。** 不采用，因为 Session 使用的授权会取决于进程环境状态，而不是其持久日志。此前对该设计的拒绝继续有效：实时更新是已记录的决定，不是按调用读取设置。

**向既有事件追加空 `allowedModels` 数组并将其视为关闭。** 不采用，因为这会用新含义复用既有判别值，使现有读取方拒绝或误读有效日志。独立事件让既有日志和既有读取方保持既定行为。

**保存每路由的推理强度允许列表。** 不采用，因为用户决定针对子级模型，而强度 id 与兼容性属于精确适配器路由。可选的每路由强度只记录默认值，不缩小模型可显式选择的强度范围。

**只更新保存设置变更的那个 Session。** 不采用，因为偏好是 Host 范围的；其他存活 Session 及其子级会保留过期授权。所有存活 Agent 一起对齐。

**只在下次委派时更新子级。** 不采用，因为子级自身也可以委派；收窄的偏好必须在该 Agent 启动下一个子级前对其生效。设置服务更新每个存活 Agent 自己的 Session。

**保留创建时快照并要求新建对话。** 不采用，因为这会让所报告的偏好变更对当前对话和恢复的 Session 都无效，而本决定正是要移除该行为。

## Consequences

- 设置编辑会改变每个存活 Agent（包括子 Agent）的授权；恢复的 Session 会在首个新请求前对齐。变更对其下一次发现或委派调用可见，并记录在该 Session 日志中。
- 初始事件为兼容性保持不变。只有精确路由集合或某条路由的默认强度不同才追加变更事件；相同路由重排不会追加任何事件。
- 仅当调用方省略强度时才应用路由默认强度。设置卡按模型列出适配器公布的强度；显式调用值不受策略限制。
- 旧版 harness 遇到新的必需事件时会拒绝重建该 Session，而不是静默沿用过期授权。不提供降级支持。新读取方保留旧日志，因为缺少变更事件时初始事件仍然有效。
- 发现与执行继续读取共享投影，因此授权路径只有一个来源和一个执行点。
- 测试覆盖存活的顶层与子级更新、恢复的 Session、未变化的路由集合、每路由默认强度变更、发现结果，以及偏好变更后的执行器拒绝。
